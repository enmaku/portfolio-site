# Pet base data: what the Foundry packs and the rules corpus hold

Research for issue #511 (CritCrafter Pets tab map, #508). Question: do the Foundry `foundryvtt/pf2e` packs, as pinned in our ingest, and the Firestore `rulesEntries` corpus carry the base data the Pets tab needs?

**Short answer:** the corpus holds pet *prose* (feats, class features, familiar-ability descriptions where they sit in an ingested pack) but **no structured base stats for any pet kind**. Per-animal companion stats are not in the Foundry packs at all (only one animal, Cat, appears as an embedded item in four pregen actors). Eidolon base data is in the packs as description HTML plus a few rule elements, and the eidolon class features are already ingested as `classFeature` text. Familiar abilities have a dedicated pack (117 docs) that the ingest does **not** read, so 113 of 117 do not resolve today.

## Sources and method

## What the ingest reads (and does not)

`PACK_TYPES` maps exactly seven top-level pack directories to corpus types:

| Pack dir | Corpus type |
| --- | --- |
| `feats` | feat |
| `spells` | spell |
| `actions` | action |
| `class-features` | classFeature |
| `heritages` | heritage |
| `backgrounds` | background |
| `equipment` | equipment |

Everything else is skipped, including `familiar-abilities`, `ancestries`, `classes`, `iconics`, `paizo-pregens`, `pathfinder-npc-core` and every bestiary. Documents without `system.publication.title` are also skipped.

**Entry shape** (`buildData` in the lib): document id `<type>:<foundry-slug>` (with `-<pack>` suffix on slug collisions); `data` fields `name`, `nameKey`, `type`, `level`, `traits[]`, `rarity`, `actionType`, `actions`, `bulk`, `price`, `spell` (spells only), `item` (equipment only: itemType, category, group, usage, range, acBonus, dexCap, hardness, hp), `description` (sanitised HTML with enrichers flattened), `aliases[]`, `license` (`ORC` or `OGL`, from `system.publication.license`), `remaster`, `title` (source book). There is **no field for rule elements, ability modifiers, HP, speeds or any per-pet numbers**; those are dropped at ingest.

Last production ingest (runbook log): 6486 feat / 2036 spell / 591 action / 881 classFeature / 357 heritage / 547 background / 6005 equipment, 16903 total.

## Per pet kind

### Animal companions

- **Per-animal base stats (Bear, Wolf, Bird, ... at young): not in the packs.** There is no `animal-companions` or similar pack, and no ancestry-pack entries for them. The only place the structure appears is *embedded* in pregen actors: four character actors (`iconics/lini/droogami-level-1|3|5.json`, `paizo-pregens/little-trouble-in-big-absalom/precious.json`) carry an embedded `ancestry` item "Cat", a class item "Animal Companion" and an action item "Cat Support Benefit". Those embedded items have usable structure: the Cat ancestry has `hp: 4`, `reach: 5`, ability `ActiveEffectLike` rules (Str +2, Dex +3, ...), and an HTML block listing size, melee attacks and damage, ability mods, HP, skill, senses, speed, special, support benefit and advanced maneuver; license OGL, remaster false, title "Pathfinder Core Rulebook". The "Animal Companion" class item holds the maturity-independent base: HP 6, perception 1, saves 1/1/1, unarmed 1, unarmored 1, trained acrobatics and athletics, Int -4, plus `self:specialized` predicate modifiers (Int +2, Dex +1 when specialized). Only Cat exists this way; the other animals are presumably generated by the pf2e system code, which this checkout does not contain. Not in `rulesEntries`: the ingest never reads `iconics` or `paizo-pregens`.
- Related pregen/NPC docs: `kingmaker-bestiary/dog-ekundayos-companion.json` and two PFS `animal-companion-wolf-*` NPCs are monsters, not base data.
- **Maturity (young / mature / nimble / savage), incredible, specializations:** present only as feat prose. Ranger: `feats/class/ranger/level-1/animal-companion-ranger`, `level-6/mature-animal-companion-ranger`, `level-10/incredible-companion-ranger`, `level-16/specialized-companion-ranger`; Druid equivalents (`animal-companion`, `mature-animal-companion-druid`, `incredible-companion-druid`, `specialized-companion-druid`); also `paragon-companion`, `masterful-companion`, `apex-companion` and archetype variants. All are ORC (remaster) in the ranger samples read. They are ingested as `feat` entries, but their text says only "becomes a nimble or savage companion, gaining additional capabilities determined by the type of companion", so the numeric consequences (the per-animal nimble/savage tables) are not in them. The ten named specializations (ambusher, bully, daredevil, racer, tracker, wrecker, ...) have **no pack entries**; searches for them only hit unrelated equipment and NPCs.
- Verdict: the Pets tab cannot derive an animal companion's stat block from the packs or the corpus. Fill from AoN or Pathbuilder's own tables (below).

### Familiars

- **Abilities:** `packs/pf2e/familiar-abilities/` holds 117 JSON docs (86 top level, 11 in `specific-familiary-abilities/`, rest in subfolders), all `type: action`, `category: familiar`. Licences: ORC 83, OGL 34 (sources include Player Core 50, Tian Xia Character Guide 15, Rage of Elements 9, Book of the Dead 9, Grand Bazaar 8, Divine Mysteries 7, Player Core 2 5, others). Some carry real rule elements, for example `tough.json` has `FlatModifier hp "2 * @actor.level"` ("max HP increase by 2 per level"), so master-derived numbers are partly machine-readable in the pack even though prose-only in `description`.
- **Corpus status:** the pack is **not in `PACK_TYPES`**, so it is not ingested. Only 4 of the 117 names also exist in ingested packs by name (`Share Senses` and `Shadow Step` as actions, `Play Dead` and `Echolocation` as feats). Fixture check: `taraan-skyseeker.json` lists familiar abilities `Accompanist`, `Elemental`, `Speech`, `Burrower`, `Independent`, `Tough`; all six exist in `familiar-abilities/` and none exist in any ingested pack, so they currently resolve as `name_unmatched` (assemble hints familiar names as `['action','feat']`). Note that `packs/pf2e/actions/familiar/` holds a single file (`shadow-step`), so the shipped Familiar group on the Actions screen works only for the few names that happen to collide.
- **Specific familiars** (for example the `specific` field, `Elemental Wisp (Earth)` in the Taraan fixture) have no dedicated pack; `familiar-abilities/specific-familiary-abilities/` holds only 11 related abilities. The `Familiar` feat (`feats/class/shared-class-feats/level-1/familiar.json`) grants "Pet" via `GrantItem` and holds no stats. The remaster per-class familiar feats (`alchemical-familiar`, `leshy-familiar`, `undead-familiar`, `glyph-familiar`, `spirit-familiar-animist`, `elemental-familiar-kineticist`, ...) are ingested feats with prose.
- Master-derived rules (familiar HP 5 per master level, AC/saves/Perception/skills from the master, 2 abilities + 1 per extra, Tough etc.) are rules text in the Familiar section of the core rules, not in any pack entry here beyond the rule elements on individual abilities. The sheet function has to hold them as code or a committed table.
- Verdict: adding `familiar-abilities` to `PACK_TYPES` (as `action`, since `category: familiar`; or a new `familiarAbility` type) is the cheap, high-value fix. It brings 117 entries, ORC/OGL tagged.

### Eidolons (summoner)

- **Type base data is in the packs and already in the corpus as prose.** `class-features/summoner/` holds 15 eidolon type docs, each `type: feat`: Aberrant, Angel, Anger Phantom, Beast, Construct, Demon, Devotion Phantom, Dragon, Elemental, Fey, Ooze, Plant, Psychopomp, Swarm, Undead. `class-features` is in `PACK_TYPES`, so they are ingested as `classFeature` with description HTML. Licences vary: ORC for most (Impossible Magic, Battlecry!), **OGL for Construct and Psychopomp (Secrets of Magic) and Elemental (Rage of Elements)** despite the remaster note, so the per-entry tag matters.
- **Content per type** (in the description HTML, in a regular pattern): tradition, traits, home plane, size, suggested attacks, eidolon attributes (for example Dragon: Con +1, Int +1, Wis +0, Cha +1), skills, senses, language, speed, then the initial and level-gated abilities. Structured parts are limited to rule elements: a `ChoiceSet` for tradition/skill, `ActiveEffectLike` for skill ranks and tradition, and a `subfeatures` object (`languages.granted`, `proficiencies`, `senses`, `suppressedFeatures`). Numeric base stats must be parsed from HTML or transcribed. The `pets_eidolons` Pathbuilder table (below) has the same data in columns, including AC and dex cap.
- Shared rules: `class-features/summoner/eidolon.json`, `eidolon-defensive-expertise|mastery`, `eidolon-unarmed-expertise|mastery`, `eidolon-weapon-specialization`, `greater-eidolon-specialization`, `eidolon-symbiosis`, `eidolon-transcendence`, `shared-reflexes|resolve|vigilance`, `evolution-feat`, `instant-manifestation`, `twin-juggernauts` (all ingested as `classFeature`).
- **Evolutions:** evolution feats are ordinary summoner class feats (`feats/class/summoner/level-*/`, for example `glider-form`, `nimble-form`, `airborne-form`, `steed-form`, `towering-size`, ...) and archetype ones. Ingested as `feat`. Names resolve today (the Pathbuilder feat list already carries them).
- Pregen eidolon NPCs exist (`pathfinder-npc-core/creature-companions/beast-eidolon.json`, `pfs-season-5-bestiary/quests/*-eidolon`) but are bestiary actors and are not read by the ingest.
- Note per the map: eidolons are not in the Pathbuilder export arrays; they appear only as `specials`/`feats` on the Summoner. So the type must be inferred from the special name ("Dragon Eidolon"), which matches these classFeature entries by name.

### Construct companions (inventor)

- `class-features/construct-innovation.json` (OGL, Pathfinder Guns & Gears; ingested as `classFeature`) holds the initial modification list (Accelerated Mobility, Amphibious Construction, Increased Size, ...) as prose, plus the Command rules. Class feats `advanced-construct-companion`, `incredible-construct-companion`, `prototype-companion`, `paragon-companion`, `construct-shell`, `manifold-modifications` exist under `feats/class/inventor/` and are ingested as feats (prose). The construct's **base statistics table** (HP, ability mods, attack, speed, AC) is not in any pack entry I found. `inventorMods` is the Pathbuilder export field that carries the chosen modifications.
- Related archetype data: Clockwork Reanimator "Reanimated Companion" feats (`feats/archetype/clockwork-reanimator/`) are prose only.

### Other pet-ish kinds

Drake Rider, Mammoth Lord, Rivethun, Beastmaster and Commander companions exist as feat prose under `feats/archetype/**` and `feats/class/commander/**`, ingested as feat entries with no stats. Pathbuilder has `pets_followers` for Commander followers, so the export or Pathbuilder tables would have to be the data source.

## What is missing and where to fill it

1. **Ingest change (cheap):** add `familiar-abilities` to `PACK_TYPES` (type `action` or `familiarAbility`; also copy rule-element facts such as the `FlatModifier hp` into an `item`-style `data.facts` if the function should compute familiar HP from them). Needs a runbook count update and the 10% guard thought through (about 117 added documents on about 16.9k).
2. **Animal companion per-animal stats and specializations:** not in the packs. Options: (a) Pathbuilder's own `pets_animals` (36 columns: name, size, melee1..., str..cha, hp, skill, senses, speed, burrow/climb/swim/fly, special, support, advanced maneuver), `pet_animal_advancements`, `pets_animal_specializations` tables; (b) AoN (`elasticsearch.aonprd.com`, category for animal companions) fetched at ingest, as aliases already are; (c) system source of `pf2e` (upstream `src/`), not in this checkout. AoN's licence does not pass to us (ADR 0031), and Pathbuilder tables are its own work, so the choice has a legal side (see `docs/critcrafter/LICENCE.md`; counsel review is still open). Prefer deriving from the Paizo rules via the ORC/OGL Foundry or system data where possible, and commit a small hand-checked table for the sheet function otherwise (about 30 animals).
3. **Eidolon numbers:** the 15 type blocks are regular enough to parse at ingest into a structured `eidolon` fact object (attributes, skills, senses, speed, size, tradition) from the HTML, or to transcribe once into a committed table. AC base and dex cap per eidolon type live in Pathbuilder's `pets_eidolons` (`ac1,dexcap1,ac2,dexcap2`) and in the rules text (Eidolon section), not as pack fields.
4. **Construct companion base stats:** transcribe from the Guns & Gears / Rage of Elements text (committed table) or take from AoN; not found in packs.
5. **Familiar master-derived rules:** committed constants in the function (5 HP per level, uses master's numbers, ability counts), checked against the Pathbuilder Pets screen as the map says.
6. **Name parsing:** unrelated to base data but blocks lookups: Pathbuilder packs nickname and kind into one string (`Giant Widow (Nyame) - Young Scorpion`), so the animal key must be taken from the `animal` field of `pets[]`, not the name.

## Licence notes

- Every ingested entry carries `license` from `system.publication.license`, `ORC` or `OGL`, plus `remaster` and `title`; the viewer already shows these per entry (SPEC, LICENCE.md).
- Familiar abilities: 83 ORC, 34 OGL. Eidolon types: 12 ORC, 3 OGL (Construct, Psychopomp, Elemental). Construct innovation: OGL. Cat companion ancestry: OGL (Core Rulebook, `remaster: false`).
- If the Pets tab shows data transcribed from Pathbuilder or AoN rather than corpus entries, the per-entry licence tag would not exist for it. The existing counsel caveats in `docs/critcrafter/LICENCE.md` (ORC share-alike boundary for derived text, AoN compilation layer) apply and should be extended to cover whichever source is chosen.

## Caveats

- This checkout has no `src/`, so I could not confirm where pf2e keeps generated animal companion data; it is almost certainly in the system TypeScript or static JSON, not in packs. The pinned SHA clone that the runbook describes (sparse `packs/pf2e` only) has the same limit, so fixing this means either widening the sparse checkout or sourcing elsewhere.
- Counts come from one-off scans of this SHA; re-run if the pinned SHA changes.
- I did not open the many-pets Oracle or dragon-eidolon fixtures: they were not committed on this branch (the fixtures present show `pets: []` for every file and a single familiar in `taraan-skyseeker.json`).
