# 08 — Export, Storage and Integrations

Pathbuilder has no public API. Everything that leaves the app does so through one of
four channels: **IndexedDB**, **localStorage handoff**, **server endpoints**, or
**Firebase**. This document covers all of them plus the export formats.

## 1. Local persistence

### 1.1 IndexedDB — `pathbuilder2e_db` (version 3)

| Store | Key | Value |
| --- | --- | --- |
| `saves` | `webID` (UUID) | Character, as a **JSON string** |
| `saveIDs` | `webID` | `{characterName, classLevel, timestamp, webID, isStarbuilderCharacter}` |
| `data` | `data137`, `data_remastered80`, `data_starbuilder27` | Raw LZ-string rules text |
| `customFiles` | UUID | Custom pack JSON |
| `customBGs` | UUID | Custom background |
| `folders` | UUID | Save folder |
| `portraits` | UUID | Portrait image blob |

There is also `pathbuilder2e_firebase_db` (version 2) used to cache Firebase data.

Notes:

* `saveIDs` is what the **Open Character** dialog lists; it carries
  `classLevel` as a display string like `"Dwarf Cleric 1"`.
* Because `saves` values are strings, a re-implementation must `JSON.parse` on read
  and `JSON.stringify` on write — matching the original exactly, or old saves will not
  load.
* Deletes remove from both `saves` and `saveIDs`.
* Folders are a flat store; the character references its folder by `folderID`.

### 1.3 sessionStorage

`gmModeID` — set when launching GM Mode, cleared on `beforeunload`.

## 2. Companion pages

Heavy output is rendered by **separate top-level HTML pages** that read their payload
from `localStorage` (or a query parameter) and then render with plain DOM/Canvas
libraries. They are not part of the SPA bundle.

| Page | Payload | Content |
| --- | --- | --- |
| `pdf.html` | `pdfObject` | Legacy character sheet |
| `pdfremastered.html` | `pdfObject` | Remastered character sheet |
| `pdfstarbuilder.html` | `pdfObject` | Starfinder sheet |
| `statblock.html` | `pdfObject` | Stat block |
| `spellbook.html` | `spellbook` | Printable spellbook |
| `export.html` | `spellbook` | Export view |
| `json.php?id=N` | — | Server-side JSON viewer |
| `launch.html?build=N` | — | Share link landing |

The `pdfObject` shape is the *export JSON* described in
[03-character-model.md](./03-character-model.md) §6, plus print options.

> **Clone note:** this handoff pattern is the easiest part to modernise. A clone can
> render sheets client-side and skip the localStorage round-trip, but must still be
> able to *read* `pdfObject`-shaped data if it wants to interoperate.

## 3. Export JSON

### 3.1 Shape

See [03-character-model.md](./03-character-model.md) §6 for the full field list. The
top-level envelope is:

```json
{ "success": true, "build": { … } }
```

`success: false` responses carry an error message instead of `build`.

### 3.2 Feat tuple

```json
[ name, null, category, level, slotKey, relation, parentSlot ]
```

* `category` ∈ `Ancestry Feat`, `Class Feat`, `Skill Feat`, `General Feat`,
  `Heritage`, `Awarded Feat`, `Archetype Feat`, `Background Feat`, …
* `relation` ∈ `"standardChoice" | "parentChoice" | "childChoice"`
* `parentSlot` is `null` for top-level feats.
* The second element is always `null` (a legacy placeholder).

Generated by `Lft(...)` (bundle ~79069), which walks the slot tree recursively.

### 3.3 Proficiencies

Flat numeric ranks: `0=Untrained, 2=Trained, 4=Expert, 6=Master, 8=Legendary`.
Keys are lowercase (`fortitude`, `reflex`, `will`, `perception`, `classDC`, `heavy`,
`medium`, `light`, `unarmored`, `advanced`, `martial`, `simple`, `unarmed`,
`castingArcane|Divine|Occult|Primal`, `acrobatics`, `arcana`, `athletics`, `crafting`,
`deception`, `diplomacy`, `intimidation`, `medicine`, `nature`, `occultism`,
`performance`, `religion`, `society`, `stealth`, `survival`, `thievery`, `piloting`,
`computers`).

### 3.4 Spell casters

```json
{
  "name": "Wizard",
  "magicTradition": "arcane",
  "spellcastingType": "prepared",
  "ability": "int",
  "proficiency": 2,
  "focusPoints": 0,
  "innate": false,
  "perDay": [5,2,0,0,0,0,0,0,0,0,0],
  "spells":    [ {"spellLevel": 0, "list": ["Shield"]} ],
  "prepared":  [ {"spellLevel": 0, "list": ["Shield"]}, {"spellLevel": 1, "list": []} ],
  "blendedSpells": []
}
```

* `perDay` is 11 entries (cantrips + ranks 1–10).
* `spells` = the known/repertoire list; `prepared` = per-rank prepared lists.
* For a spontaneous caster `prepared` is empty and `spells` carries everything.

### 3.5 Focus

```json
"focusPoints": 0,
"focus": { "…": { "abilityBonus": …, "proficiency": …, "itemBonus": …,
                  "focusCantrips": [], "focusSpells": [] } }
```

### 3.6 AC

```json
"acTotal": { "acProfBonus": 3, "acAbilityBonus": 1, "acItemBonus": 0,
             "acTotal": 14, "shieldBonus": null }
```

### 3.7 Two export-shape traps

Both verified against the bundle and `export-json-sample.json`:

**1. `attributes` are raw base numbers, and `bonushp` is misnamed.**

The fields are populated at bundle line 78506:

```js
i.zhf_1.ahf_1.oh7_1 = i.xhf_1.v1p_1.h3z(i.yhf_1).y3f_1,   // ancestryhp
i.zhf_1.ahf_1.ph7_1 = i.yhf_1.f3d(i.xhf_1).v3d_1,         // classhp
i.zhf_1.ahf_1.qh7_1 = i.xhf_1.u1p_1.q96(i.yhf_1),         // bonushp
i.zhf_1.ahf_1.rh7_1 = i.xhf_1.u1p_1.r96(i.yhf_1);         // bonushpPerLevel
```

| Export field | Actually holds |
| --- | --- |
| `ancestryhp` | Ancestry HP, raw (`ancestries_new.hp`) — **no Con** |
| `classhp` | Class HP, raw (`classes_new.hp`, e.g. `6` for Wizard) — **no Con** |
| `bonushp` | **Per-level** class-feature HP (`q96`) — *not* a flat bonus, despite the name |
| `bonushpPerLevel` | **A count of HP feats** (`r96`: Toughness, Dragon's Tenacity, …), *not* an amount |

So the export gives you `ancestryhp + classhp` and two *per-level* adjustments. A
consumer must still add `Con modifier × level` itself:

```
maxHP = ancestryhp + (classhp + bonushp + bonushpPerLevel + conMod) × level
```

> **Erratum (bundle 112.0, read 2026-11-22):** `bonushp` is a **flat** HP total, not a per-level
> amount, and is *not* multiplied by level. Only `bonushpPerLevel` (the feat count) is
> multiplied. The correct formula is
> `maxHP = ancestryhp + (classhp + conMod) × level + bonushp + bonushpPerLevel × level`
> (before drained and the Stamina variant). The bracketed form above and the table row for
> `bonushp` are wrong whenever `bonushp ≠ 0`. `bonushp` is the sum of (a) the archetype
> "Resiliency" feats (Barbarian, Fighter, Monk, Champion, Ranger, Exemplar, Guardian and the
> Starfinder Operative/Solarian/Soldier equivalents): 3 HP × (1 + the number of that
> archetype's archetype-feat picks that require its Dedication), and (b) HP effects on
> user-made custom content (flat, per level or per half level, min 1). Built-in rules data
> carries no other source. Verified against two exports: Dwarf Fighter L5 Con +3 with Toughness shows 80 HP (`bonushp: 0`), and with Barbarian Dedication plus Resiliency shows 86 HP (`bonushp: 6`).

The sample (Human Wizard, Con +1, level 1) reports `ancestryhp: 8`, `classhp: 6`,
`bonushp: 0`, `bonushpPerLevel: 0` → `8 + (6 + 0 + 0 + 1) × 1 = 15` HP. Note the
`classhp: 6` is the bare printed number, confirming Con is **not** folded in.

**2. `size` is an ordinal, not an index into the nine-name array.**

| `size` | `sizeName` |
| --- | --- |
| `0` | Tiny |
| `1` | Small |
| `2` | **Medium** |
| `3` | Large |
| `4` | Huge |
| `5` | Gargantuan |
| `6` | Colossal |

The bundle's `j35(i)` switch confirms `0 → Tiny`, `2 → Medium`. These are the same
numbers the internal size constants use (`s2z_1..x2z_1 = 0..5`), **not** an index into
`r2z_1 = ["Fine","Diminutive","Tiny","Small","Medium",…]`. A clone that indexes the
nine-name array with `2` gets `"Tiny"` — wrong by two steps. **Always use `sizeName`.**

## 4. Server endpoints

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/version.json` | GET | `{displayVersion, versionName, jsVersion}` — Cloudflare-protected |
| `/app/login/` | — | Google login flow |
| `/app/builds/` | — | Saved build storage |
| `/app/builds/<id>` | GET | Fetch a saved build |
| `https://pathbuilder2e-data.b-cdn.net/Pathbuilder2eWebRemastered<ver>.js` | GET | The bundle |
| `https://pathbuilder2e-data.b-cdn.net/data137.txt` | GET | Legacy rules data |
| `https://pathbuilder2e-data.b-cdn.net/data_remastered80.txt` | GET | Remastered rules data |
| `https://pathbuilder2e-data.b-cdn.net/img/<name>` | GET | All images/icons |
| `json.php?id=N` | GET | Server-side JSON export view |
| `launch.html?build=N` | GET | Share landing page |

Version checks: `_i(R_).fij` re-fetches `/version.json` every **30 minutes**
(`setInterval(..., 18e5)`) and on `visibilitychange`; if `jsVersion` differs it shows a
"Reload" dialog.

## 5. Sharing

The **Share Copy of Character** flow:

1. Requires the character to exist locally (the "First Save" dialog appears
   otherwise, offering *Save to Local Folder* / *Save to GDrive*).
2. Uploads the build; the server returns a numeric id.
3. Produces `shareCode` + `editToken` and a `launch.html?build=N` URL.

`editToken` grants write access; `shareCode` is read-only. `emailedBuildID` records the
server-side id.

## 6. Cloud storage

* **Google Drive** — `cloudStorage: true`, `googleFileID`. Files are stored in the
  user's Drive under the app folder. Requires Google Identity Services login
  (`client_id 405471180910-…apps.googleusercontent.com`).
* **Firebase Realtime DB** — `pathbuilder-encounters-default-rtdb.firebaseio.com`,
  used by GM Mode and the live "connected player" feature. Character fields
  `firebaseID` / `prefConnectedGameID` / `prefConnectedPlayerID` track it.

### 6.1 GM Mode

`Launch GM Mode` switches the shell into a GM view (`Switch to GM Mode` /
`Return to Character Mode`). It shares a session via Firebase; players `Connect to GM`
with a game id. `sessionStorage.gmModeID` is set for the duration.
`prefHasUsedGMMode` / `prefNoGMModeDialog` suppress the intro dialog.

### 6.2 Campaign Management

`Campaign Management` stores campaign records (local + importable). A campaign can
mark certain content as GM-only; when a player connects, the app warns:

> "This campaign has options that are not available in the free version of
> Pathbuilder and will not be applied to your character."

(That string is emitted by `Eu(...)` in the bundle.)

## 7. Backup / restore

`Backup and Restore` (sidebar → Data) with buttons **Backup**, **Restore**, **Cancel**:

* Backup exports the whole local database (all saves + custom content) as a file.
* Restore imports it, replacing local data.
* `prefLastExportedDatabase` records the last backup.
* `Local Database Backup` is the underlying dialog title used in some flows.
* The warning string is constant: **"Warning: Clearing site data in your browser will
  delete your local saves!"**

## 8. PDF / print output

Three sheet variants plus a stat block. Each is a separate page receiving `pdfObject`.
The payload includes the export build plus presentation options (paper size,
portrait/landscape, which sections to include, colour mode). `Character Sheet PDF`
opens the appropriate variant based on the character's mode
(`pdfremastered` for Remastered, `pdfstarbuilder` for Starfinder, `pdf` for legacy).

## 9. Payments

* **Stripe** and **PayPal** SDKs are loaded in `app.html`.
* A one-time purchase unlocks cloud features; `prefAccount`, `prefOrderID`,
  `prefUserID`, `prefUserName` cache the result, and `prefAccountUpgradeFailed`
  records failures.
* The free tier still allows unlimited local characters.

## 10. Analytics / diagnostics

* `Report Bug (v112.0)` opens a form (Accept / Cancel) that posts to the server.
* A Cloudflare beacon is loaded in `app.html`.
* No third-party analytics beyond that.

## 11. Things a clone must preserve for interoperability

1. **`saves` values are JSON strings** — not objects.
2. **`saveIDs` keys are the same UUIDs as `saves`.**
3. **`saveIDs.classLevel` is a display string**, e.g. `"Dwarf Cleric 1"`.
4. **Data cache keys** are exactly `data137` / `data_remastered80` /
   `data_starbuilder27`.
5. **The character JSON key names** — they are the serialized form; renaming breaks
   every existing save.
6. **The export JSON field names and the feat-tuple shape** — third-party tools and
   the `json.php` viewer rely on them.
7. **`pdfObject` / `spellbook` localStorage keys** if you keep the companion pages.
8. **`prefLastCharacterID`** so a clone can pick up where the original left off.
9. **`webID` as the primary key**, with `characterRef` as a display short id.

## 12. Integration surface summary

```
┌──────────────┐  IndexedDB (saves, saveIDs, data, customFiles, customBGs,
│  Pathbuilder │             folders, portraits)
│     SPA      │  localStorage (pref*, pdfObject, spellbook, colorMode)
│              │  sessionStorage (gmModeID)
└──────┬───────┘
       │
       ├─► data CDN        (rules tables, images, the bundle itself)
       ├─► version.json    (hot-swap version check)
       ├─► /app/builds/N   (server-side saved builds, json.php viewer)
       ├─► Google Identity + Drive (login, cloud saves)
       ├─► Firebase RTDB   (GM mode, live play)
       ├─► Stripe / PayPal (one-time unlock)
       └─► companion pages (pdf*, statblock, spellbook, export) via localStorage
```
